# Releasing

## Local build

```sh
pnpm release
```

Builds universal (arm64 + x86_64) release binaries, packages `dist/NotchNotch.app` and creates `dist/NotchNotch-<version>.dmg`. Without credentials the build is ad-hoc signed and only suitable for testing on your own Mac.

For a distributable build:

```sh
xcrun notarytool store-credentials notchnotch-notary --apple-id <id> --team-id <TEAMID>
NOTCHNOTCH_SIGN_IDENTITY="Developer ID Application: Name (TEAMID)" \
NOTCHNOTCH_NOTARY_PROFILE=notchnotch-notary pnpm release
```

The app, `ExtensionRunner` and bundled helpers are signed inside-out with the hardened runtime, a secure timestamp and these entitlements:

| Target | Entitlements |
| --- | --- |
| `NotchNotch.app` | Apple Events, Calendars (responsible process for helpers) |
| `ExtensionRunner` | `cs.allow-jit` for JavaScriptCore |
| `MusicAdapter.app` | Apple Events |
| `CalendarAdapter.app` | Calendars |

## Checklist

1. Update the version in `package.json` (the app version is derived from it) and move **Unreleased** in `CHANGELOG.md` to the new version.
2. `pnpm check`
3. Commit, then tag: `git tag v<version> && git push origin v<version>`.
4. The **Release** workflow builds, signs, notarizes and creates a draft GitHub release with the DMG. It needs the secrets listed at the top of `.github/workflows/release.yml`.
5. Install the DMG on a clean Mac, connect Music and Calendar, and publish the draft.

The app icon is generated by `swift scripts/make-icon.swift <dir>.iconset` followed by `iconutil -c icns`.
